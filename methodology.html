乌兹别克斯坦 B2B 决策人线索挖掘

从「3000 条名单只出 1 个决策人」到「按翻页数线性放量」｜2026-11-14｜口径取自 v4 交付表
01 · CORE LOGIC

核心逻辑

1.1 诊断：不是额度问题，是三层错配

错配表现修正
国家路由LinkedIn 职位库、Lusha 邮箱库偏英语/科技/欧美；乌国汽车进口商多为家族式中小企业，不在库里换成本国工商登记 + 本地黄页 + 垂直交易平台 + 商会名录
数据源栈姓名在工商「法定代表人」，电话在黄页 / 平台展厅，两者不在同一处拆成「主体 / 身份 / 号码」三段分别取数，用主键合并
主体清洗名单混着自然人名义进口、报关行、一台一单车商；这些没有采购决策链先按 R01–R08 分流：自然人进 L3、报关行只留号码当引路人
最容易踩的口径坑：14 位代码一定是自然人；9 位 STIR 里也混着自然人，不能按长度判主体类型，必须结合名称 + 法律形式 + OKED 行业码一起判。

1.2 主线：把「找人」拆成四段

① 主体识别
STIR / hash / 规范名		→ ② 身份锁定
工商 CEO / 创始人		→ ③ 号码获取
JSON-LD / SSR / 黄页		→ ④ 交叉验证
去重 / 分级 / 留痕

每段换成本地真正有的公开源，再用同一主键串起来。决策人姓名只认工商登记法定代表人字段，电话只认页面公开字段，不靠联系人库拼。

1.3 扩量引擎：种子池把一次性任务变成管线

深翻分页造种子
17 精准词 + 38 品牌 × 55 页		→ 抽 12 位企业 hash
12,452 个待抓主体		→ 按汽车相关度排序
品牌/精准词优先		→ 分批抓 + 断点续跑
8 线程 / 每轮消费剩余

线索量不再取决于名单，而取决于翻多少页。种子池只造一次，后续每轮只是按新优先级消费剩余 hash，无需重新探路。

02 · RULES & SOURCES

口径与数据源

2.1 三重主键（一切去重的基础）

主键形态用途 / 坑
STIR / TIN9 位数字，按文本存防前导零丢失；9 位里混有自然人，不能单独判主体类型

03 · EXECUTION

执行步骤（按顺序，不要跳步）

  1. 洗名单 → 定主键：按 TIN 去重（存文本），执行 R01–R08 分流自然人 / 报关行 / 一台一单；官方源核存在性与 active 状态。输出：干净的企业主体清单
  2. STIR 直查工商：/search/organizations/?q=<STIR> → hash → 详情 JSON-LD。输出：CEO / 创始人 / 电话 / OKED
  3. 造种子池：精准行业词 + 品牌词深翻到分页上限，抽 12 位 hash，保留「词 + 页码」标签。先测分页上限，再决定要不要换源
  4. 按相关度分批抓详情：优先级 = 整车/商用车品牌 + дилер/авто/шины 精准词 > 泛贸易/物流/消费电子词；8 线程、每 25 条落盘、按 hash 全轮去重。输出：待抓池 + 已抓档案，可断点续跑
  5. 号码 / 姓名反查：phones tab 查同号企业，founders / managers tab 查名下企业；姓名要求全名（含父称）token 重合 ≥80%，仅姓+名相同判同名不同人。
  6. 补渠道层：avtoelon 官方展厅 + yellowpages 强相关页 + 公司名反查，覆盖工商/黄页都抓不到的展厅与经销体系。
  7. 三重去重 + 规范化：hash（抓取层）→ 规范名 + 主号码（合并层）→ 独立主体（统计层）；号码 E.164、来源合并、双源交叉提置信度。
  8. 分级打标 → 验号 → 合规触达：L1–L4 + A/B/C/D 打标，D 类剔除但留档；手机号先验 TG/WA，固话由会俄语者致电；保留退订 / 删除通道。

3.1 关键代码逻辑：种子池 + 续跑

# ① 造种子：搜索页全文抽 hash，保留来源词与页码
seeds[h] = f"{word} / p{page}"      # re.findall(r'/en/organization/[a-f0-9]{12}/', html)

# ② 优先级：相关度高的先消费
def prio(label):
    w = label.split(' / p')[0]
    if w in BRANDS or w in PRECISE: return 0      # 品牌 / дилер·авто·шины
    if w in LOGISTICS or w in ELECTRONICS: return 2
    return 1

# ③ 断点续跑：已抓 hash 全轮累积，改 MAX 即可继续扩量
done = {x['hash'] for f in RESULT_FILES for x in load(f) if x.get('hash')}
targets = sorted((h for h in seeds if h not in done), key=lambda h: prio(seeds[h]))[:MAX]
with ThreadPoolExecutor(max_workers=8) as ex:
    records = list(ex.map(parse_detail, targets))   # 每 25 条落盘
续跑命令（无需重新探路） MAX=3000 WORKERS=8 python3 fetch_orginfo_round4.py — 自动跳过已抓 hash。
MAX_PHONES=1508 python3 fetch_reverse_tabs.py — 只让 OKED 45/46/47 的新主体入表。
v4 抓完仍剩 6,525 个种子，但多为泛贸易 / 物流 / 消费电子词，相关度会低于本轮已抓批次。

04 · QUALITY & ITERATION

质量闸门与迭代逻辑

4.1 五道闸门（不满足就不进主表）

#闸门规则
1号码有效只留 9 位有效号；短号 / 8 位残缺号降级；@mail.ru 是乌国常用真实邮箱，不能当占位符误杀
2三层去重hash → 规范名+主号码 → 独立主体；同主体多号标「同主体多号」，不重复计客户
3行业相关OKED 45/46/47 正向、42/84/85/94/70/71/52 剔除；无汽车特征词归 C 待判，不许冒充 A/B
4身份校验全名（含父称）token 重合 ≥80%；D 类驾校/协会/政府/院校剔除但完整留档
5留痕每条必带 来源 URL + 数据时点 + 置信度 + 号段运营商 + 触达建议；外呼前到 stat.uz 复核董事变更
两条硬红线 ① 查不到就留空，绝不推定：抽查 12 家无 CEO 的档案，源站明确写 No data available，不是解析漏抓；黄页同样无负责人字段。
② 失败路径不计入达标数字：v4 黄页 496 页只让 31 家进主表，其余标「是否纳入主表=否」留在档案表。

4.2 四次「误判 → 修正」（最值得复用）

误判实测修正后的逻辑
翻到 p12 就以为没结果?q=дилер&page=50 仍满页 10 条换源之前先测分页上限
姓名 / 号码反查 0 命中搜索其实有 organizations / founders / managers / phones 多 tab按目标字段选对应 tab，不用默认 tab 反查
姓名命中就算同一人7 条「命中」里 5 条父称不同，是同名不同人全名 token 重合 ≥80% 才认
宽筛能凑量黄页 495 家带号，严格判汽车相关只剩 31 家，其余是面包厂 / 银行网点 / 外国机构宽筛池直接放弃，留痕但不计客户数

4.3 已证伪，不要再试

?oked= 是假参数（所有值返回同样 8 条）｜goldenpages.uz、2gis.uz、myorg.uz 整站 403｜avtoelon 完整展厅 API 需私有 appKey、其他目录全 404（只有 /yangi-avto/salonlar/ 有效）｜yellowpages 宽筛命中率 31/495｜自然人姓名反查 0 命中｜给「无负责人字段」档案补名不可能。把死路写进台账，下一轮不重走。

4.4 一句话逻辑 + 合规边界

把「找人」拆成四段、用本地主键串起来 → 用深翻分页把线索量做成可续跑的管线 → 用 OKED + 名称特征词 + 全名校验 守质量 → 用失败台账让下一轮不重走。

合规：依据 ZRU-547 / ZRU-666 / ZRU-776 第 30 条，只采公开来源并留存来源与用途；Telegram bot 不得主动发起陌生对话，广告触达须事先同意；跨境传输评估「充分保护」或明示同意；仅用于 B2B 商务联络，不用于个人画像或转售。批量触达前请当地法务复核。

统计口径：独立主体=按规范名去重；号码点=主表带有效号码行数；去重号码=按 E.164 去重；本轮净新增=本轮出现 + 不在上轮主表 + 来自本轮新采源（不含老主体字段更新）。
